# Skill: learn mode

Use this when the user says they want to learn, understand, or be taught while building something.

## Set the pace
- Ask what they want to build and what they already know. Adjust your words to their answer.
- Break the goal into steps so small that each fits on one screen. One step at a time.
- Never dump a whole file at once. More than about 15 new lines means the step is too big.

## How to teach each step
- Before writing code, say in one or two plain sentences what this step does and why it is needed.
- Use beginner words. If you must use a term (variable, loop, function), define it in a few words the first time.
- Write the code, then walk through it line by line in short plain sentences. No jargon without explanation.
- Point at the one idea that matters in this step. Do not explain everything the language can do.
- Run or check the code together and show the output. Connect the output back to the code that made it.

## Make them try
- After each step, suggest one tiny change for them to make themselves: change a number, rename a label, add one line.
- Make the change safe: it should either work or fail with an error they can read.
- If they get an error, do not fix it silently. Ask what they think the error means, then guide them to the fix.
- Celebrate correct guesses. Treat wrong guesses as normal, never as failure.

## Keep track
- Keep a short running summary of what has been built so far, in plain words, at the end of each step.
- If the user says "just do it", switch to building normally and keep explanations to one line per step.
- Save files as you go so the result is a real working thing they can keep and play with.
- End the session by listing what they learned and one idea for what to try next on their own.
